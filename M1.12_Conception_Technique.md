## 1. Architecture retenue

```
Request → VeilleArticleController ─┬─ VeilleArticleQuery (liste, filtres, curseurs)
                                   ├─ HtmlContentSanitizer (purifier + post-passe DOM)
                                   └─ ImageUrlPolicy (validation des src d'images)
```

| Composant | Responsabilité | Justification |
|---|---|---|
| `VeilleArticleController` | `index` + `show` : authorize, collecte des paramètres, rendu, en-tête CSP | Mince — conventions existantes |
| `App\Services\VeilleArticleQuery` | **Requête unique de périmètre** : veille + propriétaire + rétention + filtres + tri + curseur voisins + options de filtre | Logique partagée liste/navigation → distincte, testable |
| `App\Services\HtmlContentSanitizer` | HTMLPurifier configuré + post-passe DOMDocument (attributs `img`, retrait des images refusées) | Service réutilisable (alertes futures, contenus tiers) |
| `App\Services\ImageUrlPolicy` | Validation des URL d'images distantes (hôte, IP, DNS) | Responsabilité distincte, testable isolément |
| Vues Blade `veilles/articles/{index,show}` | Présentation | Conventions `x-app-layout` |

Pas de FormRequest dédié : filtres = query-string simples
(`source_id` int, `keyword` string ≤ 255, `page` int) validés/castés
dans le contrôleur.

**API du service de requête :**

```php
final class VeilleArticleQuery
{
    /** Base périmétrée : article_veille × articles, propriétaire + rétention. */
    private function base(Veille $veille): BelongsToMany;

    /** Filtres optionnels source_id / matched_keyword. */
    private function applyFilters(BelongsToMany $q, ?int $sourceId, ?string $keyword): BelongsToMany;

    public function paginate(Veille $v, ?int $src, ?string $kw, int $perPage = 20): LengthAwarePaginator;
    public function neighbor(Veille $v, Article $a, ?int $src, ?string $kw, string $dir): ?Article; // 'prev'|'next'
    public function matchedKeywords(Veille $veille): Collection; // distinct, périmétré, pour le filtre
    public function filterSources(Veille $veille): Collection;   // sources réellement présentes, périmétrées
}
```

## 2. Routes et autorisations

```php
Route::get('/veilles/{veille}/articles', [VeilleArticleController::class, 'index'])->name('veilles.articles.index');
Route::get('/veilles/{veille}/articles/{article}', [VeilleArticleController::class, 'show'])->name('veilles.articles.show');
```

- Middleware `auth` (bloc existant dans `routes/web.php`).
- `index` : `Gate::authorize('view', $veille)` (VeillePolicy existante).
- `show` : `Gate::authorize('view', $veille)` **+** vérification
  explicite de l'association **dans la fenêtre de rétention** :

  ```php
  ArticleVeille::where('veille_id', $veille->id)
      ->where('article_id', $article->id)
      ->where('user_id', $veille->user_id)          // isolation explicite
      ->whereHas('article', fn ($q) => $q->whereRaw(
          'COALESCE(published_at, collected_at) >= ?', [$cutoff]))
      ->exists() or abort(404);
  ```

  404 (pas 403) pour ne pas confirmer l'existence ; un article associé
  mais **hors rétention** est inaccessible — la fenêtre s'applique
  partout, pas seulement à la liste. `user_id` jamais pris de la requête.
- Paramètres : `source_id` (cast int), `keyword` (string), `page` (int)
  — tout le reste ignoré (liste blanche, §4).

## 3. Stratégie des requêtes

```php
private function base(Veille $veille): BelongsToMany
{
    $cutoff = now('UTC')->subMonths(VeilleRematcher::RETENTION_MONTHS); // 6
    return $veille->articles()                       // pivot user_id injecté (veille persistée)
        ->with('source')                             // pas de N+1 (nom de source)
        ->whereRaw(
            'COALESCE(articles.published_at, articles.collected_at) >= ?',
            [$cutoff],
        );
}
// filtres
->when($src, fn ($q) => $q->where('articles.source_id', $src))
->when($kw !== null && $kw !== '', fn ($q) => $q->wherePivot('matched_keyword', $kw))
// tri stable portable
->orderByRaw('COALESCE(articles.published_at, articles.collected_at) DESC')
->orderByDesc('articles.id')
->paginate(20)->appends($navParams)
```

- `COALESCE` : identique SQLite/MariaDB (pattern déjà en prod dans
  `VeilleRematcher`). L'index `published_at` ne couvre pas le COALESCE —
  acceptable au volume (fenêtre 6 mois) ; pas d'index fonctionnel (MVP).
- **Pagination — `appends`, jamais `withQueryString()`** :
  `withQueryString()` reporterait **tous** les paramètres arbitraires de
  la requête (contradiction avec la liste blanche §4). Le paginateur
  reçoit `$navParams = array_diff_key($params, ['page' => true])` — les
  paramètres validés §4 **sans `page`** (l'ajouter figerait tous les
  liens de pagination sur la page courante). `page` n'est repris que
  dans les liens prev/next et retour liste (§4).
- `matchedKeywords()` : `whereNotNull('article_veille.matched_keyword')
  ->distinct()->orderBy('matched_keyword')->pluck(...)` sur la **base
  périmétrée** → pas d'option de filtre sans résultat.
- `filterSources()` : `distinct` des `articles.source_id` de la base
  périmétrée joint à `sources` — pas les sources théoriques de la veille.
- Toutes les requêtes (liste, options, voisins, accès direct) passent par
  `base()` : un seul point d'entrée SQL, le pivot `user_id` est injecté
  automatiquement (veille persistée) en plus du `veille_id` de la
  relation.

## 4. Navigation précédent/suivant

Même requête filtrée + comparaison de curseur sur
`(COALESCE(published_at, collected_at), id)` :

- `prev` = article plus récent : `(coalesce > c) OR (coalesce = c AND id
  > a.id)` ordonné `coalesce ASC, id ASC`, `first()`.
- `next` = article plus ancien : condition symétrique `<`, ordre
  `DESC`, `first()`.
- Pas de scan ni de chargement en mémoire ; `first()` renvoie `null` en
  bordure → lien absent (comportement correct si l'article courant est
  hors-ensemble filtres).
- **Propagation des paramètres — liste blanche stricte** : seuls
  `source_id`, `keyword`, `page` **valides** sont repris dans les liens
  prev/next/retour/pagination :

  ```php
  $raw = $request->query();

  /** Valeur entière positive, ou null — sans cast hasardeux. */
  $positiveInt = static fn ($v): ?int =>
      is_scalar($v)
      && filter_var($v, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]) !== false
          ? (int) $v
          : null;

  $params = array_filter([
      'source_id' => $positiveInt($raw['source_id'] ?? null),
      'keyword'   => is_string($raw['keyword'] ?? null)
          && ($k = trim($raw['keyword'])) !== ''
              ? mb_substr($k, 0, 255)
              : null,
      'page'      => $positiveInt($raw['page'] ?? null),
  ], static fn ($v) => $v !== null);   // conserve "0" : seuls les null sortent
  ```

  Jamais de `query()` brut ni `->appends($request->all())`.
- **Validation des types avant conversion** : les paramètres HTTP sont
  des chaînes de requête arbitraires — chacun est contrôlé **avant**
  toute conversion :
  - `source_id` : scalaire + `FILTER_VALIDATE_INT` avec `min_range=1`
    → entier positif, sinon ignoré ;
  - `keyword` : `is_string` puis `trim` + `mb_substr(…, 0, 255)` ;
  - `page` : même règle entière positive ;
  - **tableaux, objets et valeurs malformées ignorés proprement** :
    `is_scalar`/`is_string` court-circuitent avant `filter_var`/cast —
    aucun cast de tableau en chaîne ou en entier (qui lèverait
    « Array to string conversion » → `ErrorException` sous Laravel).
    Paramètre invalide → absent de `$params` (valeur par défaut :
    filtre inactif), **jamais d'erreur 500**.
  - `array_filter` avec `fn ($v) => $v !== null` : sans callback, PHP
    éliminerait aussi la chaîne `"0"` — mot-clé légitime conservé.
  Répartition : les liens **prev/next et retour liste** portent les
  trois paramètres (`source_id`, `keyword`, `page`) ; le **paginateur**
  ne reçoit que `source_id`/`keyword` via `appends($navParams)` (§3) —
  `page` n'y est jamais appensé.
- Article `show` hors filtres actifs : accessible si associé + dans la
  fenêtre (la vérification porte sur l'association, pas les filtres) ;
  les voisins se calculent avec les filtres fournis.

## 5. Configuration HTMLPurifier

`figure`/`figcaption`/`time` ne font **pas** partie de la définition
HTML 4.01 par défaut : définition personnalisée requise (vérifié —
`HTML.Allowed` seul ne suffit pas pour des éléments inconnus).

```php
$config = HTMLPurifier_Config::createDefault();
$config->set('HTML.Allowed',
    'p,br,a[href|title],img[src|alt|title|width|height],strong,b,em,i,'
    .'ul,ol,li,blockquote,pre,code,h2,h3,h4,figure,figcaption,'
    .'table,thead,tbody,tr,th,td,hr,time[datetime]');
$config->set('URI.AllowedSchemes', ['http' => true, 'https' => true]);
$config->set('HTML.Nofollow', true);
$config->set('Attr.EnableID', false);
$config->set('AutoFormat.RemoveEmpty', true);
$config->set('HTML.DefinitionID', 'veille-articles');
$config->set('HTML.DefinitionRev', 1);
$def = $config->maybeGetRawHTMLDefinition();
$def->addElement('figure', 'Block', 'Flow', 'Common');
$def->addElement('figcaption', 'Block', 'Flow', 'Common');
$def->addElement('time', 'Inline', 'Flow', 'Common');
$def->addAttribute('time', 'datetime', 'Text');
```

**`figcaption` — définition vérifiée par test sur v4.19.1 réel**
(2026-11-03) : texte, paragraphes, liens, listes, `em`/`strong`
conservés à l'identique avec les types `Inline` et `Block` — c'est le
contenu `Flow` qui gouverne l'intérieur. `Block` est retenu : c'est la
classification fidèle (élément de flux — empêche `figcaption` imbriqué
dans un contexte inline type `<p>`). Effet secondaire vérifié :
purifier auto-complète `alt` manquant sur `img` (`alt="i.png"`).

- `DefinitionID`/`DefinitionRev` requis pour mettre en cache la
  définition personnalisée ; incrémenter `DefinitionRev` si la whitelist
  évolue.
- `URI.AllowedSchemes` s'applique à `href` **et** `src` →
  `javascript:`/`data:`/`file:` tués par construction.
- `script/iframe/object/embed/form`, `on*`, `style` : absents de la
  whitelist → supprimés. HTML malformé : rééquilibré par purifier.
- `target` non whitelisté dans le contenu ; le lien original est rendu
  **hors** contenu assaini avec `target="_blank" rel="noopener noreferrer"`.
- Assainissement **au rendu** uniquement (l'ingestion reste fidèle).

**Signature et valeurs nulles** :

```php
public function sanitize(?string $html): string
{
    $html = trim($html ?? '');
    return $html === '' ? '' : $this->postProcess($this->purifier->purify($html));
}
```

`?string` obligatoire : `content` et `summary` sont NULLables en base —
aucun appel ne provoque de TypeError. `null`, chaîne vide et contenu
réduit à `''` par la purge (balises interdites seules) retournent tous
`''` → déclenchent le fallback.

**Fallback de contenu — évaluation post-assainissement :**

```php
$body = $sanitizer->sanitize($article->content);      // 1. contenu
if ($body === '') {
    $body = $sanitizer->sanitize($article->summary);  // 2. résumé
}
// 3. $body toujours '' → vue « métadonnées + lien original »
```

Gère le cas « contenu composé uniquement de balises interdites »
(script/iframe exclus → `''` après purge → bascule au résumé).
`AutoFormat.RemoveEmpty` facilite la détection « vide ».

## 6. Sécurité des images distantes — stratégie de validation

**Contexte (décision actée, inchangée)** : les images sont chargées
**directement par le navigateur** depuis leur serveur d'origine — pas de
proxy, pas de téléchargement/stockage serveur. Le SSRF du collecteur ne
s'applique pas (contexte client, pas serveur), mais l'URL d'image reste
une entrée non fiable fournie par le flux : elle est validée côté
serveur **avant d'être émise dans le HTML**, sans que le serveur ne
fasse la requête lui-même.

### 6.1 Chaîne de contrôle

1. **HTMLPurifier** élimine les schémas non `http(s)`
  (`javascript:`/`data:`/`file:`) et normalise la syntaxe URI.
2. **Post-passe DOM** (§7) : chaque `<img src>` survivant est validée
   par `ImageUrlPolicy::isAllowed(string $src): bool`.
3. URL non conforme → **le nœud `<img>` est supprimé entièrement** (pas
   seulement `src`) : aucune requête navigateur possible, pas de balise
   cassée ; le `figure`/`figcaption` éventuel reste lisible.

### 6.2 `ImageUrlPolicy` — contrôles ordonnés (vérifiés)

Réutilise `App\Services\Feed\IpAddressPolicy` (allowlist « globalement
routable » déjà éprouvée en M1.10 — aucune duplication, aucune
dépendance nouvelle) ; reprend les règles de normalisation d'hôte de
`FeedUrlValidator` (ext-intl présent).

**Ordre des opérations** — l'IP littérale est détectée **avant** toute
conversion IDN (`idn_to_ascii` ne s'applique qu'aux véritables noms
d'hôtes ; l'appliquer à une IP serait à la fois inutile et dangereux :
vérifié, `idn_to_ascii('fe80::1%eth0')` renvoie l'entrée inchangée, ce
qui pourrait faire passer une forme non contrôlée en aval) :

1. **Parser et valider l'URL** : `parse_url`, schéma `http`/`https`
   (redondant avec Purifier — défense en profondeur à coût nul).
2. **Identifiants intégrés refusés** : `user` ou `pass` présent
   (`http://user:pass@host/`, `http://evil.com@127.0.0.1/`) → rejet.
3. **IP littérale — détection et vérification** : retrait des crochets
   (`parse_url` retourne l'hôte IPv6 **avec** `[]`, vérifié) puis
   `filter_var($host, FILTER_VALIDATE_IP)` :
   - IP détectée → `IpAddressPolicy::isGloballyRoutable()` ; toute IP
     non globalement routable → rejet :
     - IPv4 : privé (10/8, 172.16/12, 192.168/16), loopback (127/8),
       link-local (169.254/16), réservé/spécial (0/8, 100.64/10 CGN,
       192.0.0/24, doc TEST-NET, benchmark, multicast 224/4, 240/4,
       broadcast) — table IANA explicite, supérieure aux flags
       `NO_PRIV_RANGE`/`NO_RES_RANGE` de `filter_var` ;
     - IPv6 : n'admet que l'unicast `2000::/3` hors blocs spéciaux
       (Teredo, 6to4, NAT64, documentation, SRv6…) — loopback `::1`,
       link-local `fe80::/10`, unique-local `fc00::/7` rejetés par la
       porte `2000::/3` ;
     - **IPv4-mappées `::ffff:a.b.c.d` normalisées en IPv4 à
       l'intérieur de `IpAddressPolicy`** puis jugées selon la règle
       IPv4 — pas de contournement par une forme IPv6 ;
   - IP détectée et globalement routable → URL admise (fin du contrôle).
4. **Chemin nom d'hôte** (uniquement si `filter_var` n'a pas reconnu
   une IP) : trim, minuscules, retrait du point final FQDN
   (`exemple.fr.`), puis `idn_to_ascii($host, IDNA_DEFAULT,
   INTL_IDNA_VARIANT_UTS46)` ; échec ou chaîne vide → rejet. Le même
   filet attrape les restes non-DNS (zone-id `[fe80::1%eth0]` : pas
   d'IP reconnue à cause du `%`, puis rejet en 5/6/7).
5. **Hôtes numériques ambigus** : 1 à 4 parties séparées par des points
   toutes numériques (décimal, `0x` hexa, `0` octal, mixtes) → rejet.
   `2130706433`, `0x7f000001`, `0177.0.0.1`, `127.1` seraient
   réinterprétés en IPv4 par la libc/le navigateur (même règle que
   `FeedUrlValidator`, validée en M1.10).
6. **Noms locaux** : mono-label (`intranet`, `nas`, `localhost`) →
   rejet ; suffixe réservé/local → rejet :
   `localhost`, `.localhost`, `.local`, `.lan`, `.internal`, `.corp`,
   `.home.arpa`, `.test`, `.example`, `.invalid`, `.onion`.
7. **Pré-résolution DNS (best-effort, fail-closed — voir §6.2.1)** :
   `gethostbynamel()` (A) + `dns_get_record($host, DNS_AAAA)` ; rejet si
   **aucun** enregistrement ou si **l'un** des résultats n'est pas
   globalement routable selon `IpAddressPolicy`. Cette couche attrape le
   cas trivial « nom public dont l'enregistrement A/AAAA pointe déjà
   vers une IP privée » (attaque sans rebinding, la plus accessible).

**Cas vérifiés par exécution réelle** (PHP 8.3.36 + vrai
`IpAddressPolicy`, 2026-11-03) :

| Entrée | Chemin | Résultat |
|---|---|---|
| `[2606:4700:4700::1111]` | littéral IPv6, 2000::/3 | **admis** |
| `[::1]` loopback / `[fe80::1]` link-local / `[fd00::1]` ULA | littéral IPv6 | rejeté |
| `[::ffff:8.8.8.8]` mappée publique | littéral → IPv4 | admis |
| `[::ffff:127.0.0.1]` mappée loopback | littéral → IPv4 | rejeté |
| `[fe80::1%eth0]` / `%25eth0` zone-id | pas d'IP (`%`) → hostname → mono-label | rejeté |
| `bücher.de` | IDN → `xn--bcher-kva.de` | admis si DNS public |
| `example.com.` | point final retiré | admis si DNS public |
| `localhost` / `LOCALHOST` | mono-label | rejeté |

Pas de restriction de port : un port exotique n'aide pas l'attaquant
DNS (il choisirait :443), le navigateur possède sa propre blocklist de
ports, et les CDN légitimes utilisent des ports variés.

#### 6.2.1 Résolution DNS — stratégie et performances

Les appels `gethostbynamel`/`dns_get_record` sont **synchrones** : sans
API de timeout en PHP, chaque hôte unique peut coûter jusqu'au délai du
résolveur système (typiquement plusieurs secondes sur résolveur
injouable). Contrôles de volume, fail-closed conservé :

- **Mémoïsation par requête** : un tableau `host => verdict` évite de
  résoudre deux fois le même hôte (un article peut répéter un CDN).
- **Ordre économique** : le DNS n'est interrogé qu'en dernier, après
  les rejets gratuits (littéral, formes numériques, noms locaux).
- **Plafond d'images par document** : au-delà de **50** éléments `<img>`
  contrôlés, les suivantes sont rejetées (fail-closed) — borne un
  document pathologique.
- **Plafond d'hôtes uniques résolus** : au-delà de **25** hôtes
  distincts par document, les hôtes supplémentaires sont rejetés sans
  résolution (fail-closed) — borne la latence pire cas à
  ~25 × timeout résolveur, et une image abusive ne peut pas générer
  de requêtes DNS en rafale vers des noms aléatoires.
- **Risque résiduel documenté** : un résolveur système lent dégrade le
  rendu de la page de lecture proportionnellement au nombre d'hôtes
  uniques (≤ 25) — acceptable au regard de la taille typique d'un
  article ; aucune résolution asynchrone ni cache persistant n'est
  introduit (pas de dépendance ni de service supplémentaire).

### 6.3 Limite documentée — DNS, rebinding et chargement direct

La pré-résolution (6.2.7) réduit mais **ne peut pas éliminer** le
risque : la résolution faite par le serveur et celle du navigateur sont
distinctes dans le temps et dans l'espace.

- **DNS rebinding / TOCTOU** : un domaine attaquant peut répondre une IP
  publique au serveur puis une IP privée au navigateur (TTL nul, double
  flux).
- **Split-horizon DNS** : une IP publique « innocente » peut résoudre
  vers une cible interne dans le réseau de l'utilisateur (ou
  inversement).
- Seuls un proxy serveur ou un téléchargement local élimineraient le
  problème — **écartés par la décision fonctionnelle de chargement
  direct**, assumée et documentée ici.

En pratique l'attaquant retenu par ces contrôles doit déjà publier un
enregistrement DNS changeant entre la vérification et le chargement —
barrière réelle, résidu accepté pour le MVP.

### 6.4 Limite documentée — redirections HTTP

`ImageUrlPolicy` valide l'URL **initiale** uniquement. Avec le
chargement direct par le navigateur — sans proxy ni téléchargement
intermédiaire par Veille — le serveur d'origine peut répondre par une
redirection HTTP (3xx) vers une autre adresse :

- Veille ne contrôle pas les redirections suivies par le navigateur —
  elles ont lieu **après** la validation, côté client ;
- une URL initialement publique et admise peut rediriger vers une
  adresse privée ou locale ;
- la validation initiale ne garantit donc pas la conformité de toutes
  les destinations successives de la chaîne.

**`ImageUrlPolicy` ne protège pas contre les redirections HTTP** :
aucun contrôle côté serveur n'existe sur la chaîne de redirection du
navigateur. L'élimination complète du risque exigerait un proxy ou un
téléchargement serveur — **non proposé** : cela modifierait la décision
fonctionnelle de chargement direct déjà validée. Résidu accepté en
cohérence avec ce choix.

### 6.5 CSP et confidentialité

En-tête `Content-Security-Policy` posé sur les réponses des deux routes
articles :

```
default-src 'self';
script-src 'self' 'unsafe-eval';
style-src 'self' 'unsafe-inline';
img-src 'self' https: http:;
font-src 'self';
object-src 'none';
frame-ancestors 'self';
base-uri 'self';
form-action 'self'
```

- `img-src` ouvert aux hôtes distants (requis par le chargement direct).
- **`'unsafe-eval'` justifié** : Alpine.js 3 (bundlé via Vite, servi
  depuis `'self'`) évalue les expressions `x-data`/`x-on` via
  `new Function()` — `script-src 'self'` seul **casserait** les vues
  existantes (dropdown navigation, modales, formulaires veilles). Les
  scripts externes/inline restent bloqués ; l'éval ne concerne que les
  chaînes déjà dans le DOM. Migration future possible vers
  `@alpinejs/csp` (réécriture de tous les `x-data` — disproportionnée
  pour le MVP, documentée pour évolution).
- **Test obligatoire** : Feature vérifiant la présence de l'en-tête sur
  les deux routes + test manuel des deux pages CSP activée (Alpine
  fonctionnel).
- Les hébergeurs d'images voient l'IP et (sans mitigation) le referer de
  l'utilisateur — limite intrinsèque du chargement direct ; mitigée par
  `referrerpolicy="no-referrer"` (§7).

## 7. Post-traitement DOMDocument — spécification vérifiée

> Comportements vérifiés par exécution réelle le 2026-11-03 sur
> **PHP 8.3.36 + libxml 2.9.14** (environnement de production).

```php
private function postProcess(string $purified): string
{
    $dom = new DOMDocument();
    $loaded = $dom->loadHTML(
        '<?xml encoding="utf-8"?>'.$purified,
        LIBXML_NOERROR | LIBXML_NOWARNING,
    );
    $body = $loaded ? $dom->getElementsByTagName('body')->item(0) : null;

    // Fail-closed : échec d'analyse ou d'extraction → chaîne vide, qui
    // déclenche le fallback. Jamais de retour du HTML non post-traité :
    // les images n'auraient pas passé ImageUrlPolicy (§6).
    if ($body === null) {
        return '';
    }

    // getElementsByTagName retourne une NodeList VIVE : instantané
    // obligatoire avant toute suppression, sinon des éléments sont sautés.
    $images = iterator_to_array($dom->getElementsByTagName('img'));
    $checked = 0;
    foreach ($images as $img) {
        if (++$checked > 50                              // plafond §6.2.1
            || ! $this->imageUrls->isAllowed((string) $img->getAttribute('src'))) {
            $img->parentNode->removeChild($img);          // rejet §6
            continue;
        }
        $img->setAttribute('referrerpolicy', 'no-referrer');
        $img->setAttribute('loading', 'lazy');
    }

    $out = '';
    foreach ($body->childNodes as $node) {
        $out .= $dom->saveHTML($node);
    }
    return $out;
}
```

### 7.1 Faits vérifiés (ne pas supposer)

- **`<?xml encoding="utf-8"?>` obligatoire** : libxml 2.9 ne détecte pas
  l'UTF-8 sans PI ni `<meta charset>` ; sans le préfixe, les accents et
  entités sont **corrompus** (mojibake constaté).
- **`LIBXML_NOERROR | LIBXML_NOWARNING`** absorbe le HTML malformé sans
  bruit.
- **`LIBXML_HTML_NOIMPLIED | LIBXML_HTML_NODEFDTD` REJETÉ — vérifié
  cassant** : sous libxml 2.9.14, ce mode émet « Tag figure invalid » et
  **perd le contenu** (`figure`, `table`, `a` supprimés du résultat).
  Ne pas l'utiliser.
- Avec la PI, libxml enveloppe le fragment dans `<html><body>` :
  extraire les **enfants de `body`** rend exactement le contenu purifié,
  sans artefact ajouté.
- `saveHTML($node)` sérialise chaque nœud : accents préservés en UTF-8,
  entités nommées converties en caractères UTF-8, `&amp;` ré-échappé
  correctement dans les `href`/`src`.
- Texte seul en entrée → enveloppé `<p>` par libxml (comportement
  accepté) ; entrée vide → `''`.
- **Fail-closed** : `loadHTML()` en échec (`false`) ou `<body>`
  indisponible → `postProcess` retourne `''` → le fallback de contenu
  s'applique. Le HTML purifié **n'est jamais retourné sans
  post-traitement** : ses images n'auraient pas passé `ImageUrlPolicy`
  ni reçu `referrerpolicy`/`loading` — la sûreté ne se dégrade jamais,
  au pire le contenu n'est pas affiché.

### 7.2 Garanties de sûreté du résultat

- Le post-traitement ne **crée** ni nœud ni contenu : il ne fait que
  supprimer des `<img>` et ajouter deux attributs inertes
  (`referrerpolicy`, `loading`) sur des éléments déjà admis par la
  whitelist Purifier. Aucune surface scriptable réintroduite — le HTML
  final reste dans la fermeture de la whitelist.
- **Aucune regex de transformation HTML** (règle absolue) — DOM natif
  uniquement.
- Entrée toujours post-Purifier : le post-traitement ne voit jamais
  `script`/`on*`/`iframe`.

### 7.3 Tests dédiés (unit, sanitizer)

- Balises autorisées conservées à l'identique (`p`, `a`, `table`,
  `figure>figcaption`, `time[datetime]`, listes, titres).
- Image `https:` conservée + `referrerpolicy="no-referrer"` +
  `loading="lazy"` ajoutés ; image `http:` idem.
- Image rejetée par `ImageUrlPolicy` (IP privée, `javascript:` ayant
  survécu — non possible, identifiants intégrés, nom local) → nœud
  entier absent.
- Accents (`éàü`), entités (`&eacute;`, `&mdash;`, `&amp;` dans
  `href`), tableaux, figures, liens : inchangés après aller-retour DOM.
- Aucun attribut `on*`, `style`, `target` réintroduit.
- Entrée `''` → `''` ; entrée texte nu → sortie sûre.
- `src` absent ou vide → rejet (pas d'attribut inventé).
- Échec d'analyse DOM (entrée qui fait échouer `loadHTML`) → `''`, le
  HTML purifié n'est pas retourné tel quel.
- 51+ images : la 51ᵉ et suivantes sont supprimées (plafond §6.2.1).

## 8. Cache HTMLPurifier — comportement vérifié (v4.19.1)

> Vérifications faites dans les sources `ezyang/htmlpurifier` **v4.19.1**
> (version résolue par `^4.18` au 2026-11-03) :
> `ConfigSchema/schema/*`, `DefinitionCacheFactory.php`,
> `DefinitionCache/Serializer.php`, `DefinitionCache/Null.php`,
> `Config.php`.

### 8.1 Configuration

- `Cache.SerializerPath` (string/**null**, défaut `NULL`) : `NULL` →
  cache **dans `vendor/`** (`.../DefinitionCache/Serializer`) —
  inacceptable ici. Chemin réel utilisé : `<SerializerPath>/<TYPE>`
  (`HTML`, `CSS`, `URI` créés par purifier **à l'intérieur** du chemin).
- Notre valeur : `storage_path('app/htmlpurifier')`.
- `Cache.SerializerPermissions` : défaut **`0755`** (pas null) — garder
  le défaut.

### 8.2 Comportement réel en cas de problème (vérifié)

`_prepareDir()` est appelé par `add`/`set` à chaque écriture de cache :

| Situation | Comportement v4.19.1 |
|---|---|
| `<SerializerPath>` **absent** | `trigger_error('Base directory ... does not exist', E_USER_WARNING)` → `add` retourne `false` |
| `<SerializerPath>` présent, sous-dossier `HTML` absent | `mkdir` non récursif + chmod `0755` → créé automatiquement |
| Répertoire présent **non inscriptible** | tentative de `chmod` si propriétaire, sinon `trigger_error('not writable', E_USER_WARNING)` → `false` |
| `Cache.SerializerPermissions = null` | `mkdir` silencieux seul, tout échec → warning + `false` |

**Correction importante par rapport à la conception initiale** : un
échec n'est **pas** un mode dégradé silencieux. Le `E_USER_WARNING` est
converti en **`ErrorException`** par le handler d'erreurs de Laravel →
`purify()` **lève une exception** (et le refait à chaque appel, `get()`
manquant toujours). Le check préalable est donc **obligatoire**, pas
optionnel :

```php
$path = storage_path('app/htmlpurifier');
if (is_dir($path) && is_writable($path)) {
    $config->set('Cache.SerializerPath', $path);
} else {
    $config->set('Cache.DefinitionImpl', null);   // repli vérifié
}
```

### 8.3 `Cache.DefinitionImpl = null` — repli valide (vérifié)

`DefinitionCacheFactory::create()` retourne alors
`HTMLPurifier_DefinitionCache_Null` : toutes les méthodes no-op →
**zéro I/O, zéro warning**, purify pleinement fonctionnel.
Coût : la définition (dont la personnalisée `figure`/`time`) est
reconstruite **une fois par requête** (mémoïsée ensuite dans
`$config->definitions`), au lieu d'être désérialisée — acceptable en
repli, pas un fonctionnement nominal visé.

### 8.4 Déploiement

- `storage/app/htmlpurifier/` créé au déploiement (`0755`, propriétaire
  `web18` comme `storage/app`), contenu gitignoré — à documenter dans
  `Deployment.md` lors de l'implémentation.
- Les sous-dossiers `HTML`/`CSS`/`URI` sont créés par purifier au
  premier `purify()` — rien d'autre à prévoir.

## 14. Risques résiduels et arbitrages

- **DNS rebinding / split-horizon** (§6.3) : non éliminable sans proxy —
  résidu accepté, documenté ; la pré-résolution fail-closed réduit le
  cas trivial.
- **Redirections HTTP des images** (§6.4) : la validation porte sur
  l'URL initiale ; une redirection ultérieure vers une adresse privée ou
  locale échappe au contrôle — résidu accepté, cohérent avec le
  chargement direct.
- **Latence DNS synchrone** (§6.2.1) : un résolveur lent peut dégrader
  le rendu ; borné par mémoïsation + plafonds (50 images / 25 hôtes,
  fail-closed) — pas de dépendance ni de service asynchrone ajouté.
- **`'unsafe-eval'` CSP** : requis par Alpine 3 ; migration
  `@alpinejs/csp` possible en évolution ultérieure.
- **Définition HTML5 personnalisée** : si `figure`/`figcaption`/`time`
  posaient problème à l'implémentation, les retirer de `HTML.Allowed`
  (dégradation inoffensive vers `p`) plutôt qu'ajouter une couche.
- **`HTML.Nofollow`** : proposé ; retirer si les liens du contenu
  doivent rester « propres ».
- **Tracking des hébergeurs d'images** : IP visible, referer supprimé
  par `referrerpolicy` — limite intrinsèque du chargement direct.
- **Absence de restriction de port** sur les images : arbitré
  (blocklist navigateur + CDN légitimes), documenté §6.2.
